# Design: 控制面连续性（control-ha）

## Context

当前 jinguan 单实例 + per-user JVM 锁；控制面将承担共享控制与命令。服务已 last-known，控制面短时不可用只影响变更，不影响问答/转发。

## Goals / Non-Goals

**Goals:**
- v1 控制面可备份、可恢复。
- 快照/命令不丢；版本不回退。
- 控制面可限流、可告警。

**Non-Goals:**
- v1 不做多实例 HA/跨地域多活。
- 不做服务 HA。
- 不以多实例 HA 阻塞迁移。
- 不做告警平台/值班系统，只做告警投递。

## Decisions

1. v1 单实例 + 共享 PG；调度器单实例/租约。
2. 快照/命令持久化在权威库；版本单调。
3. 备份/恢复演练 + RPO/RTO 为验收项。
4. 多实例 API/故障切换为后续触发；触发时再立 change。
5. 抗滥用：所有控制接口 per-service/tenant/IP 限速、请求大小/超时/并发上限；超限 429/413/504 + Retry-After；限值配置化；异常审计/告警；服务 last-known 不受影响。
6. 告警投递：控制面不可用/DB/备份失败、saga blocked、身份吊销、契约漂移、限流/认证异常；envelope 含 dedup_key/runbook；webhook/email 通道；重试/去重/ack；不阻塞控制写、不含敏感值。
7. 备份与清理：备份保留期显式配置；过期备份与告警投递记录按保留策略清理并审计。
8. 备份安全：加密存储；独立备份凭证/最小权限；恢复二次确认/审批并审计；备份不入仓库/公开桶；日志脱敏。
9. 告警通道安全：webhook 签名/共享密钥；目标 URL allowlist；email 独立认证；凭证不入库/日志；拒绝重放/伪造；失败重试审计。

## Risks / Trade-offs

- 单实例故障窗口 → 服务 last-known；备份/恢复；不做在线写入保证。
- 共享库成为单点 → DB 备份/恢复；控制面不依赖内存。
- 调度器重复执行 → 租约/单实例。

## Migration Plan

部署变更；无服务数据迁移；HA 触发前不引入副本协调。
